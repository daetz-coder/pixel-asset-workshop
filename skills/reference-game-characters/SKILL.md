# 根据参考图学习整套游戏画风并生成素材

从参考图提取可复用的画风档案，再按资产类别生成原创素材。用共用的色彩、形状、光照和像素表现维持整体一致性，用各类素材自己的结构与尺度保证可用。

## 选择范围

- **学习整套画风**：盘点资源包或游戏截图，选取每个有证据的类别的代表图，输出画风档案、参考索引和覆盖情况。对只有一张图或只有部分资源的情况，标注哪些规则有直接证据，哪些是从相关素材推断的，哪些还缺参考。
- **扩充已有档案**：先查已有画风和确认记录，再加入新证据或缺失类别。单个素材需求按相关类别补足证据即可。沿用已有同类基准的确认记录。
- **按画风生产**：用共享画风加目标类别规则编写提示词。跨类别批次各选同类图做锚点，并在一张场景预览里对照实际使用效果。

先读项目的 `AGENTS.md` 和已有画风档案。Tiny Swords 任务读 [整套画风档案](references/tiny-swords-art.md)。做 Tiny Swords 蓝队兵种时加读 [蓝队角色示例](references/tiny-swords.md)。角色任务读 [角色精灵流程](references/character-sprites.md)，其他资产按需读 [各类资产的制作与验收](references/asset-families.md)。

## 1. 学习并记录视觉规则

1. **收集实际参考。** 按任务选择阵营单位、人形敌军、怪物、建筑、地形、道具/资源、特效、按钮和 UI。场景截图适合看比例、层次和使用关系，原始贴图适合看色板、透明边、格网和状态；有两种证据时一起用。裁取可读的代表区域，保留文件路径、帧索引和裁框。
2. **从跨类别证据提取共性。** 记录主要镜头、形状、光照和色块处理、冷暖及明暗关系、材质色、描边与细节密度。比较同一类别内的变化，再对照其它类别。例：蓝色可以作为阵营标记同时出现在服装与屋顶，UI 仍有自己的屏幕空间材质和对比度。
3. **为每类记录固定项和可变项。** 记录该类形体、视角、比例、色板、输出规格、参考用途、目标显示环境与验收方式。区分画布、逻辑像素和显示尺寸。分清从文件测得、从图中目测估计以及这次新设计的参数。用同类已有批准图作基准。
4. **保存档案与证据。** 沿用项目约定，或写到 `assets/art-direction/<style-id>/style-profile.md`。档案至少包含：共享视觉规则、逐类规则、来源和覆盖状态、已确认基准、世界尺度与 UI 尺度、待补证据。每条具体参数能追溯到图或明确标注为设计决定。

画风档案用于后续调用和复查。只分析画风时，输出档案和关键参考索引即可。

## 2. 生成与扩展

- 实际生成位图前读取可用的 `imagegen` skill，默认使用内置 GPT Image。查看输入图并传入真实图像。注明哪张控制目标类别的形体或状态，哪张补充共用色板或场景关系。
- 新类别先做一个代表样图，已有同类基准时直接复用。人物参考适合提供世界的视觉关系。建筑形体用建筑参考，按钮状态用真实按钮参考，地形连接用地形图。
- 将档案中的共享规则、同类固定项和本次设计差异写入 [提示词模板](references/prompt-patterns.md)。按需求选择单图、单类部件或概念板，生成独立精灵时使用工具原生透明背景。保存实际提示词、图像输入和原始输出。
- 优先生成原创轮廓和结构。已批准的样图可用于同类扩展，每次重新附上基准来减少漂移。项目已有的样图确认流程按现有约定执行。
- 本地工具用于裁图、对齐、采样、拼板和校验；位图美术按用户和项目约定使用生成工具。UI 组件需要交互时，生成可用的皮肤和图标，文案、焦点和布局由界面组件实现。
- 记录工具实际回执。用户指定的版本和工具实际披露的后端分别记录。生图不可用时交付已完成的画风档案、参考和提示词，标明生成状态。

## 3. 按用途验收

在同类原图和拟使用环境中检查。使用统一的世界比例与基线看角色和建筑，使用真实控件尺寸看 UI。只统一画布大小容易掩盖真实尺度差异。

- 检查单张的识别度、透明边、轮廓、像素网格、尺寸、偏移和裁切。随附 [sprite_reference.py](scripts/sprite_reference.py) 支持 alpha、色样和边界报告，以及精灵表裁帧和身体对齐预览。
- 检查同类结构。人物看装备和脚底，建筑看占地和入口，地块看拼接，按钮看各状态切换，面板看拉伸和内容区，特效看事件点和透明边。
- 多类别结果一起放进一个代表场景。检查建筑、地形与单位的相对尺度，阵营色在单位与建筑上的一致性，资源和敌人能否从背景中区分，以及 UI 是否保持操作和阅读层级。
- 修订时附待修图和对应锚点，说明具体缺陷和需要保持的结构。实测通过的结果记录验收条件，估计或未验证的项保留标记。

## 4. 交付并留档

交付请求范围内的独立素材及必要的拼接、状态或场景预览。沿用项目命名。通用批次可在 `assets/art-runs/<batch>/` 保存提示词、对照和 `manifest.json`。已有角色批次继续使用 `assets/concepts/` 与 `assets/character-runs/`。

清单记录类别、用途、输出与原始生成文件、参考和来源、提示词、工具、规格、锚点或切片参数及状态。已验收与用户已确认分别记录。若请求动画，角色分支可衔接 `sprite-motion-prompts` 或 `wan-prime-video`。

[初版角色流程的检索依据](references/research.md) 可用于追溯设计来源。
